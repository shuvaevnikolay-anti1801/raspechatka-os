# Подключение оборудования

POS отделяет бизнес-логику от конкретных драйверов. Касса обращается к интерфейсам `FiscalProvider` и `PaymentProvider`, а выбранный адаптер уже разговаривает с оборудованием. Благодаря этому экран продажи и работа без интернета не зависят от модели ККТ или банковского терминала.

## АТОЛ 1Ф

Сейчас используется безопасный `MockFiscalProvider`: он выдаёт тестовый номер чека, но не обращается к настоящей кассе. Для рабочего подключения нужны:

1. установленный на Windows «Драйвер ККТ» АТОЛ 10.x;
2. настроенная и проверенная в утилите АТОЛ связь с ККТ;
3. выбранный способ связи приложения с драйвером и параметры устройства;
4. тест на нефискальном контуре, затем отдельная приёмка продажи, возврата и повторной печати.

Товарный чек не является фискальным: он уже печатается через системный диалог Windows и может быть отправлен на обычный принтер.

## Банковский терминал

Рабочая интеграция PAX использует установленный официальный INPAS DualConnector 2.0 через
`DCConsole.jar`, штатный `DCConsole.bat` либо legacy `DC Console.exe`. Для совместимости также распознаются
варианты имени `DCCconsole.jar` / `DCCconsole.bat`. JAR запускается напрямую через `java -jar`, EXE — напрямую,
а BAT fallback — только через фиксированный `cmd.exe` без формирования пользовательской shell-строки.

Поддержанные команды комплекта банка:

- `-o1` — продажа;
- `-o4` — отмена/возврат;
- `-o26` — проверка связи;
- `-o59` — сверка итогов.

В настройках оборудования необходимо включить INPAS и указать ID терминала. Console-компонент определяется
в стандартной папке `Program Files (x86)\\INPAS\\DualConnector` автоматически. Старый сохранённый путь продолжает поддерживаться.
Сумма передаётся в копейках, валюта — ISO 4217 `643`.

Комплект INPAS предоставляет одну команду продажи для карты и QR. Выбранный в кассе канал сохраняется
раздельно для учёта, но окончательный способ подтверждается на экране PAX. Это поведение необходимо
проверить на банковском тестовом контуре перед эксплуатацией QR.

`result.txt` и `receipt.txt` читаются в Windows-1251 после завершения процесса. Оплата подтверждена только
если SA-поле `[39]` равно `1`; exit code процесса является только технической диагностикой и сам по себе
не подтверждает и не отменяет уже полученный банковский результат. Неуспешный банковский код означает отказ,
а таймаут, signal/kill, crash без подтверждённого SA-результата или отсутствие читаемого `[39]` — неизвестный
результат. Последний вариант блокирует повторное списание до восстановления операции. Параметр `-s`
передаётся Console в секундах, внутренний timeout процесса остаётся в миллисекундах с техническим запасом.

Перед закрытием смены с картой или QR касса автоматически выполняет сверку итогов. Её также можно
запустить вручную в разделе оборудования.
