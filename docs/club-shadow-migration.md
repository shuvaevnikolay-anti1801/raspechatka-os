# Параллельный клуб — первый этап переноса

## Граница поставки

Эта поставка включает защищённый приём снимков клиентов из Google, панель настроек
в Клиенты → Клуб Распечатка и дополнительный Apps Script. Tilda и МойСклад
продолжают работать как прежде. Запись из OS в МойСклад НЕ выполняется.
Режим основной OS, перенос публичных страниц, восстановление входа через
подтверждение телефона и окончательное переключение BotHelp — следующие этапы,
не активируются этой поставкой.

## Настройка (после успешного deploy и bench migrate)

1. Создать/проверить существующую точку Ярославль, Комсомольская, 12: город,
   адрес и активность должны быть заполнены. Дубликат точки не создавать.
2. Администратору сети открыть Клиенты → Клуб Распечатка → Параллельный перенос.
3. Выбрать точку. Указать ID таблицы (часть URL между /d/ и /edit).
4. Создать случайный секрет длиной не менее 32 символов, сохранить его в менеджере
   паролей. Внести в поле ключа, включить приём, сохранить. Секрет не передавать в чат.
5. Убедиться, что часовой пояс Google-таблицы совпадает с часовым поясом сайта OS
   (для этой точки Europe/Moscow). Даты передаются как местное время.
6. Проверить настройки клуба OS: 0 каналов → 0%, 1 → 3%, 2 → 5%, максимум 2 канала.
   Скрипт НЕ перезаписывает настройки OS автоматически.
7. Сделать резервную копию исходной таблицы и сохранить текущий Apps Script.
8. В существующем Apps Script добавить НОВЫЙ файл `club_os_bridge.gs` и вставить
   содержимое `integrations/google_apps_script/club_os_bridge.js`.
   Старые doGet/doPost, BotHelp и МойСклад не заменять.
9. В Настройки проекта → Свойства скрипта добавить `RASPECHATKA_OS_SECRET`:
   тот же ключ, что в OS. Не помещать ключ в ячейку или исходный код.
10. Запустить `clubOSPreview`. Выдать разрешения на таблицу и внешние запросы.
    Успех: `ok: true, dry_run: true`. Проверяется первая карточка, изменения
    транзакционно откатываются. Это НЕ проверка всей базы.
11. Запустить `clubOSInstall`. Создаётся минутный триггер и техническая очередь.
    Полная база и последующие изменения отправляются пакетами до 15 клиентов
    за запуск. Публиковать новую версию Web App для этого триггера не нужно.
12. Проверить очередь (SENT/ERROR), панель OS и несколько карточек/согласий.

## Поведение

- Первичный перенос выполняется тем же мостом, отдельный XLSX импорт не нужен.
- Исходные ID, имена, даты, телефоны, токены, согласия и каналы сохраняются.
- Все импортированные клиенты привязываются к выбранной точке. Проверяются город
  Ярославль и улица Комсомольская с номером 12; точную запись выбирает администратор.
- Конфликт телефона с другим ID или существующая ручная карточка OS блокирует
  импорт клиента. Объединение требуется разобрать отдельно, автоматически не делаем.
- Документ клиента пересчитывается по правилам OS; несовпадение скидки/количества
  каналов отражается как DIFFERENCE. Перед использованием скидки в своей кассе
  все расхождения должны быть устранены.
- Google является владельцем импортированных карточек. Их ручное изменение и
  публичная перезапись через OS блокируются до отдельного переключения.
- История согласий дополняется по внешнему ключу; отзыв создаёт новую аудиторскую
  запись. Старые записи не переписываются. Служебные сырьевые тела старого журнала
  не импортируются, поскольку могут содержать bearer-токены.
- Прямые изменения в таблице также обнаруживаются периодической сверкой снимков.
- Подпись запроса действует 5 минут. При повторе отправки она создаётся заново.
- Принятый Event ID хранится в БД; повтор безопасен. Более старый снимок не
  перезаписывает новый. Работа сериализуется в транзакции.
- Неотправленные payload содержат персональные данные и токены: скрытая колонка
  НЕ является защитой доступа. Таблица должна быть доступна только доверенным
  администраторам. После подтверждения доставки payload очищается.
- После первичного импорта контролировать квоты Apps Script/UrlFetch.
- Снимок одного клиента ограничен 45 000 символов (лимит ячейки); при превышении
  требуется пакетный перенос его истории, скрипт сообщает об этом явно.
- Нет автоматического удаления клиентов по отсутствию строки в Google.
- Исторические записи без Client ID остаются в исходной таблице.

## Остановка и возврат

Запустить `clubOSPause` и выключить приём в панели OS. Старый клуб продолжает
работать независимо. Не удалять таблицу, токены и Apps Script. Не менять CLUB_API
на Tilda на этой стадии. Для возобновления снова выполнить `clubOSInstall`.

## Следующие этапы полного выхода из внешних систем

1. Полная сверка клиентов, дат согласий, каналов и скидок; тест реальных BotHelp
   событий и продаж, полученных из МойСклад. Сопоставление групп клуба со скидками.
2. Контролируемое переключение владельца данных с Google на OS; адаптер записи
   в МойСклад включается только после остановки прежнего писателя.
3. Публичные страницы на собственном сервере и безопасный вход с подтверждением
   владения телефоном. Один номер телефона сам по себе не является авторизацией.
4. Переключение BotHelp и собственной POS; сохранение истории покупок без дублей.
5. Отключение Google/Apps Script, Tilda и клиентского контура МойСклад только
   после приёмки. Архивы сохраняются согласно согласованному сроку хранения.

## Проверки

Pure unit tests: `python -m unittest discover -s tests -p test_club_sync_protocol.py`.
Apps Script syntax: `node --check integrations/google_apps_script/club_os_bridge.js`.
Нужны тестовый Frappe site и отдельная тестовая таблица для проверки транзакций,
разрешений, повторов, конфликтов и фактической работы триггера. Статическая
проверка не заменяет эти испытания.
