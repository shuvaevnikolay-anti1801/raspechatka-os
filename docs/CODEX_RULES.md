# Codex Rules

## Проект
Распечатка OS

## Основные правила разработки

1. Не менять архитектуру без явного указания.
2. Перед изменением искать существующий код.
3. Делать минимальные изменения.
4. Не создавать новые сервисы без необходимости.
5. Не дублировать существующую логику.
6. Сохранять обратную совместимость.

## Порядок работы

1. Найти существующую реализацию.
2. Внести минимальное изменение.
3. Проверить сборку и ошибки.
4. Описать результат.

## Git

- Один DEV = одна небольшая задача.
- Коммиты должны быть понятными.
- Не смешивать разные задачи в одном изменении.
